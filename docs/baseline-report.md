## 1. Executive Summary

A comprehensive repository audit and baseline assessment of the existing phishing link detector codebase was conducted. The application is an end-to-end cybersecurity solution comprising a FastAPI backend, a React frontend (Vite/Tailwind), a Chrome Extension (MV3), and a Scikit-learn Random Forest model with heuristic fallback.

Crucially, this audit uncovered **four pre-existing critical bugs and vulnerabilities** in the unmodified repository:
1. **Model Path Mismatch**: Trained model is saved to `backend/scripts/model.pkl`, but the API server loads from `backend/model.pkl`. The model file was missing entirely from Git, forcing the API to run in heuristic-only fallback mode.
2. **Missing Extension Icons**: The Chrome extension references `icons/icon16.png`, `icons/icon48.png`, and `icons/icon128.png`, but the `icons/` folder was omitted from the repository.
3. **Severe SSRF Risk in Core Scan Flow**: `_run_scan` unconditionally executes an unvalidated outbound HTTP GET request (`trace_redirects`) and optional headless Playwright browser navigation on every scanned URL, exposing AWS IMDS (`169.254.169.254`) and internal subnets.
4. **Vite Experimental Version Failure**: Frontend `package.json` specifies `"vite": "^8.0.12"` (resolving to `8.0.16` with the Rolldown native bundler), which fails on Windows Node 20.16 due to missing `@rolldown/binding-win32-x64-msvc` optional bindings.

## 3. Pre-Existing Bugs & Discrepancies Catalog

### Bug 1: Machine Learning Model Path Mismatch
- **Locations**:
  - `backend/scripts/train_model.py` (line 145):
    ```python
    out_path = Path(__file__).parent / "model.pkl" # -> backend/scripts/model.pkl
    ```
  - `backend/app/routers/scan.py` (line 22):
    ```python
    MODEL_PATH = Path(__file__).parent.parent.parent / "model.pkl" # -> backend/model.pkl
    ```
  - `backend/Dockerfile` (line 17):
    ```dockerfile
    RUN python train_model.py || echo "Model training skipped" # Fails: train_model.py is in scripts/
    ```
- **Consequence**: The production API server never finds the trained ML model and always operates in heuristic fallback mode.

### Bug 2: Missing Chrome Extension Icons
- **Location**: `chrome-extension/manifest.json`:
  ```json
  "icons": {
    "16": "icons/icon16.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  }
  ```
- **Consequence**: `chrome-extension/icons/` folder is missing, causing Chrome to fail extension loading or display broken placeholders.

### Bug 3: Outbound SSRF & Cloud Metadata Vulnerability
- **Location**: `backend/app/routers/scan.py:106` calls `await trace_redirects(url)` unconditionally.
- **Consequence**: In an AWS cloud environment, an attacker can submit `http://169.254.169.254/latest/meta-data/` to obtain IAM role credentials.

### Bug 4: Frontend Vite / Rolldown Binding Failure
- **Location**: `frontend/package.json` specifies `"vite": "^8.0.12"`.
- **Consequence**: `npm run build` fails on Node 20.16.0 with `MODULE_NOT_FOUND: @rolldown/binding-win32-x64-msvc`.

## 5. Architectural Assessment for AWS Deployment

### 5.1 Safe for AWS Lambda:
- FastAPI core application (via `Mangum` ASGI adapter).
- URL feature extraction pipeline (28 features, pure math/string processing).
- Heuristic detection engine.
- Scikit-learn Random Forest model inference (~2MB model file, fast CPU inference < 15ms).
- JWT authentication and authorization.

### 5.2 Requires Compatibility Adapter / Isolation:
- **Playwright Headless Screenshotting**: Playwright and Chromium binaries exceed Lambda zip package limits (250MB uncompressed) and require significant memory (1GB+) and cold-start latency (2-4s). Must either be isolated into a containerized Lambda / Fargate task or made an asynchronous background task.
- **Database**: SQLite cannot be used across ephemeral Lambda instances. Amazon RDS PostgreSQL or Aurora Serverless v2 is required for production multi-user state.
- **Rate Limiting**: In-memory dictionary must be supplemented by API Gateway throttling / WAF.
- **Redirect Tracing**: Must be safeguarded with an SSRF firewall (DNS resolution validation, private IP blocking) before any outbound connection is attempted.

## 6. Phase 0 Exit Criteria Summary

1. **What currently works**:
   - URL feature extraction (28 features).
   - Heuristic risk scoring fallback.
   - Core API routing and Pydantic validation schemas.
   - JWT authentication and password hashing.
   - Database schema definition for users, scans, API keys, and whitelists.
2. **What is broken before modifications**:
   - Model file is missing; model path in `train_model.py` does not match `scan.py`.
   - Chrome extension icons are missing.
   - Frontend build fails due to experimental `vite` rolldown binding.
   - Outbound redirect tracing is an unmitigated SSRF vector.
3. **What must remain unchanged**:
   - Existing 28 feature definitions and feature extraction vector order.
   - All existing API endpoints, request bodies, and response structures.
   - Existing database table schemas and relationships.
   - Frontend page hierarchy and navigation routes.
4. **Unknowns to resolve before deployment**:
   - AWS Account ID, Region, and target deployment budget.
   - Decision on whether screenshotting should be disabled in serverless or deployed via Lambda container image.
   - VirusTotal and Google Safe Browsing / Web Risk API credentials.
